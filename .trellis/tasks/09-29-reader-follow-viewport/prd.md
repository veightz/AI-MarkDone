# PRD：阅读器跟随视口 + 文内结构大纲（交互提案）

> **状态**：planning / 提案待 Violet & 用户确认，**本轮不写代码**。  
> **优先级**：P0（常显之后的下一条）。  
> **合并**：原 `09-29-reader-entry-unify`（文案/入口收敛）并入本单；宽屏仍见 `09-29-reader-widescreen`。

---

## 1. 问题

当前用户进阅读器的路径与「正在看哪条回复」脱节：

1. **主入口绑在消息底栏工具条**（`btnReader` →「阅读器」），用户滚动长对话时，必须滚到某条回复底部才能点；视口中间正在读的那条往往没有就近入口。
2. **右下角另有「在分屏中打开阅读器」**（`chatgptPageControlSplitView`），打开的是独立/分屏阅读器，文案与行为都像另一套功能，和回复区「阅读器」打架（原入口统一诉求）。
3. **侧栏目录条**（`ChatGPTDirectoryRail`）擅长跳转回合，不适合再塞成阅读器主触发（Violet 已否决侧轨作主入口）。
4. 长回复内部常有 **1 / 2 / 3… 或标题分段**；阅读器已有 Markdown **标题大纲**（`showOutlineInReader` / `reader-structure`），但对「纯编号段落、弱标题」识别不足，跳转体验不完整。

### 现状代码入口（调研备忘，非实现范围）

| 入口 | 文案 (zh) | 行为 | 关键文件 |
|------|-----------|------|----------|
| 消息工具条次要按钮 | 「阅读器」 | 打开页内 `ReaderPanel`，锚定该条 | `MessageToolbarOrchestrator.createReaderAction`；`ReaderPanel` |
| 右下角 stepper | 「在分屏中打开阅读器」 | `openDetachedReaderFromStepper` → 独立 reader 页 | `ChatGPTMessageStepperController`；`runtimes/content/entry.ts` |
| 设置开关 | 「独立阅读器 Split View」 | 控制底栏按钮显隐 | `showDetachedReaderControl`；`SettingsTabView` |
| 目录侧轨 | （导航预览） | **不做**阅读器主触发 | `ChatGPTDirectoryRail` |
| 阅读器内大纲 | 「Markdown 大纲」 | 基于 heading 的 `outlineItems` | `SemanticContent` → `reader-structure`；`readerPanelTemplate.renderOutlineMarkup` |

## 2. 目标

1. **阅读器入口跟随用户，不跟随消息底**：滚动时识别视口内「主读」的那条助手回复，在其附近（或视口固定位置）常驻「阅读器」chip；一点即开**当前这条**。
2. **主次分明**：视口跟随 chip = **主入口**；底栏分屏/独立阅读器 = **次入口**（保留能力，不抢主路径）；**不以目录侧轨作主触发**。
3. **入口统一（并入）**：用户可见名称收敛为「阅读器」（或主 chip「阅读器」+ 次入口明确副标，如「独立窗口」）；不再并列两套互斥说法。
4. **文内结构**：打开阅读器后，对当前回复检测标题 + `1/2/3…` 类分段，展示可跳转大纲。
5. 提案确认后，可与「工具条常显」已完成项在同一交互叙事里收口（本单不重复改常显逻辑）。

## 3. 提案 UI 放置（二选一，需确认）

### 方案 A — 贴消息 chip（推荐倾向）

- 在**当前主读助手气泡**外侧固定位置放一颗常驻 chip：「阅读器」（书本图标 + 文案）。
- 建议锚点：**气泡右上外侧**或**气泡与官方操作区之间的外侧**，避免挡住正文首行与官方 Copy 等。
- 仅对「当前主读」那一条显示一颗；切换主读时 chip **换绑**到新消息（可短过渡，忌满屏多颗）。
- 原消息底栏工具条里的「阅读器」可：降为图标-only 备份，或与 chip 同源保留（确认时二选一，见开放问题）。

**优点**：空间语义清晰——「开的就是这条」。  
**风险**：虚拟列表/消息 remount 时锚点抖动；窄屏可能与官方控件抢位。

### 方案 B — 视口固定 chip

- 在对话滚动区**视口内固定角**（建议右中或右下偏上，避开底栏 stepper）放一颗「阅读器」。
- chip 副文案或 tooltip 显示当前锚定回复的短预览（如首行 12 字 / 回合序号）。
- 点击仍打开**当前检测出的主读回复**。

**优点**：实现与 DOM remount 解耦更稳，不跟气泡布局打架。  
**风险**：「开哪条」依赖副文案，认知成本略高；易与底栏抢视觉。

### 本提案默认写法

PRD 验收按 **方案 A 为主、B 为备选** 写；实现前必须由 Violet/用户在开放问题里盖章。也可 A+B：贴消息为主、极窄屏回退为视口固定。

## 4. 滚动 / 「当前主读消息」检测规则（提案）

**候选集**：当前会话中已挂载的 **assistant** 消息根节点（与现有 `conversationSurface` / adapter 消息身份一致；streaming 中的消息默认不进入主读，或仅在「已有可提取正文」时进入）。

**主读判定（建议）**：

1. 取视口中线（或视口上方 35% 处的水平线）与各助手气泡相交的集合。
2. 在相交集合中，选 **与参考线重叠面积最大** 者；若面积接近（如相差 &lt; 10%），选 **更靠上** 的一条（稳定偏好「正在读的段」而非刚露头的下一条）。
3. 若无一相交：选 **距离参考线最近** 且部分可见的助手气泡；若仍无可见助手消息，则 **隐藏** 主 chip（或禁用并 tooltip「附近没有助手回复」）。
4. **滞后（hysteresis）**：新候选需连续 N ms（建议 120–200ms）或滚动稳定后再换绑，避免快速滑过时 chip 乱跳。
5. **用户主动打开阅读器后**：阅读器内翻页/切消息由现有 Reader 导航负责；关闭回到页面时，重新按视口规则绑定。

**非目标（检测）**：不根据用户消息气泡选主读；不以目录条 hover 状态覆盖视口检测（目录点击跳转后，等滚动稳定再重算即可）。

---

## 5. 次入口：底栏 / 分屏

- 右下角 stepper 的 `open-detached-reader` **保留**，降为次入口。
- 文案建议改为与主入口同品牌，并标明形态差异，例如：
  - 主：「阅读器」
  - 次：「阅读器 · 独立窗口」或「独立阅读器」（废止单独强调「在分屏中打开」为唯一说法）
- 行为：仍打开 detached reader（现有实验确认弹窗可保留）；**默认打开内容**优先为「当前主读」那条，若无主读则回退现有「当前会话上下文」逻辑。
- 设置项 `showDetachedReaderControl` 可继续控制次入口显隐；默认保持可见，避免老用户丢入口。

## 6. 文内结构大纲：检测启发式（提案）

阅读器内大纲在现有 **heading → `outlineItems`** 之上扩展「分段」：

| 优先级 | 模式 | 示例 | 大纲展示 |
|--------|------|------|----------|
| P0 | ATX/Setext 标题（现有） | `## 背景` | 级别 + 标题文本 |
| P0 | 行首编号段 | `1.` `1、` `1）` `（1）` `1 ` | `1 · 首行摘要` |
| P1 | 中文序数/章节 | `一、` `第一部分` `第1章` | 原文前缀 + 摘要 |
| P2 | 仅加粗首行冒充小标题 | `**结论**` 独占行 | 低置信，可默认关或折叠 |

**规则草案**：

- 编号需在 **块级开头**（段落/列表项首），避免匹配 `版本 1.2.3` 或句中数字。
- 连续编号（1,2,3…）至少 **2 项** 才生成「编号大纲」；与 heading 合并去重（同一节点不重复出现）。
- 大纲项点击：滚动到阅读器正文对应锚点（复用现有 `reader-outline-jump`）。
- 设置：可沿用/扩展 `showOutlineInReader`；若编号大纲与标题大纲同时存在，同一侧轨合并列表（标题用 Hn，编号用序号徽标）。

**非目标**：不做跨多条助手消息的全局 TOC（目录侧轨已覆盖回合级导航）。

## 7. 验收标准（提案确认后落地时）

- [ ] 滚动长对话时，主「阅读器」入口跟随 **视口主读助手回复**（方案 A 贴消息或已盖章的 B），无需滚到该消息底栏才能找到主入口。
- [ ] 任意时刻至多强调 **一个** 主读绑定；快速滚动下 chip 不狂闪（有滞后）。
- [ ] 点击主入口打开阅读器且 **startIndex / 内容锚定当前主读消息**。
- [ ] 底栏分屏/独立入口仍可用，但文案/视觉为 **次入口**；与主入口不再像两套无关产品。
- [ ] **目录侧轨不出现**新的「打开阅读器」主按钮（保持导航本职）。
- [ ] 对含 `1/2/3…` 或标题的长回复，阅读器大纲可列出并 **跳转到对应小节**。
- [ ] 无助手消息可见 / streaming-only 时有明确降级（隐藏或禁用），不误开空壳。
- [ ] i18n：`btnReader` 与次入口文案中英一致策略已写入并实现。

## 9. 开放问题（需用户 / Violet 盖章）

1. **主 chip 形态**：方案 A 贴消息 vs 方案 B 视口固定 vs A 为主、窄屏回退 B？
2. **贴消息锚点**：气泡右上外侧 / 左侧 / 紧贴官方操作行上方？
3. **消息底栏原「阅读器」按钮**：保留作备份、改为图标-only，还是主 chip 落地后移除以免重复？
4. **次入口文案终稿**：「阅读器 · 独立窗口」vs「独立阅读器」vs 其它？是否保留「分屏」字样？
5. **主入口打开形态**：默认仍走页内 `ReaderPanel`，还是跟随设置 `defaultOpenMode`（panel/fullscreen/detached）？
6. **编号大纲范围**：首版是否只做 `1.` / `1、` / `1）`，中文「一、」放到下一小步？
7. **streaming**：生成中的气泡是否允许成为主读并显示 chip？
8. **常显工具条叙事**：确认后是否在本单实现说明里写清「与 always-visible 同一轮体验收口」，还是严格只做 follow-viewport + outline？
