## 1. 实际问题与验收遗漏

- 已安装 Chrome 页面中的资料库类型按钮实际为 15px 字号、44px 行高、20px 图标，但三个按钮之间没有独立行间距；设置分类则使用带 gap 的 grid。仅把字号设成相同，并没有统一导航节奏、文字结构与选中态。`BookmarksTabView` 通过图标按钮追加文本，`SettingsCatalog` 使用自己的分类构造路径。
- 同一页面的高亮左栏显示了 conversation ID，条目来源显示通用的“会话”，而 ChatGPT 的当前会话链接和浏览器标题有名称。字段设计支持标题，问题包括标题采集缺失及不合适的显示回退。不能据此将 ID 或链接改成名称主键。
- 设置的六个信息页藏在 `<details>`“更多”下；实际打开信息页时，原设置分类仍保持选中，当前信息页入口可能被收起。既影响发现，也影响当前位置辨认。
- 右下角抽屉触发器和展开区左端各有一个品牌图标；前者只展开，后者打开资料库。消息胶囊、页面抽屉和资料库分别维护材质，按钮大小、图标尺度和接缝尚未一致。
- 本次已通过实际页面验证上述显示及展开状态。没有进行真实数据删除、改色或移动，不将此检查记作完整安装版业务验收。

## 2. 建议的信息结构

保留“资料库 / 设置”两个主模块。资料库内仍先选择书签、注释或高亮；类型下显示文件夹，右侧按照对话分组。对话是可展开的横条，显示名称和当前类型的条目数，展开后显示该对话的条目。

推荐高亮和注释共用文件夹及对话名称；原书签文件夹独立。这使同一对话只需归档、命名一次，又避免改变旧书签的移动、删除与备份规则。该范围已随推荐方案获准实施。

推荐第一版以整段对话归档：移动的是对话的文件夹归属，后续新增条目自然出现在同一文件夹。允许单条跨文件夹需要额外的条目归属层，会使同一对话在多处出现；若用户需要，再按该模型设计，不混用两种语义。

- 文件夹：全部、未分类、用户文件夹；复用书签的命名校验、最多四级、移动目标选择交互。树展开与选中分开。
- 对话：点击横条展开/收起；更多内提供自定义名称、移动整个对话、打开原页。名称空缺时显示“未命名对话”，不显示 URL 或长 ID 作为主标题。
- 条目：保留已有编辑、复制、插入、模板、改色、删除和打开原页入口；不增加高亮转注释等能力。
- 大量数据：对话目录每页 20 组；长对话内的条目每页 20 条，一次展开一个对话。折叠条目不保留隐藏正文 DOM；文件夹树最多挂载 40 行。搜索结果的计数表示匹配条目数，展开后只显示匹配项。

## 3. 数据结构建议

现有高亮已经按对话保存为 bundle：document 元数据在每个类型的对话包中保存一次，包内是条目数组；并不是每条高亮都保存一份完整 URL。注释有独立的同类结构。保留这些原始包，仅增加组织信息。

| 对象 | 建议字段 | 职责 |
|---|---|---|
| 原始高亮 / 注释包 | 现有 document、records | 正文、消息身份、引用、选区 selectors、颜色或注释内容、时间和修订号；保持原格式 |
| 文件夹 | id、parentId、name、createdAt、updatedAt | id 稳定，名字及父级可变；路径由父级计算 |
| 对话组织信息 | document、folderId、customTitle、updatedAt | document 保存现有稳定身份、来源 URL / 标题；document key 由既有函数计算，不复制条目正文 |
| 组织目录 | schemaVersion、revision、folders、conversations | 独立 namespace；一次写入完整组织目录，序列化管理变更 |

建议 namespace：`aimd:mark_library:catalog:v1`。它是用户命名和归档信息的唯一持久化来源；资料库展示索引仍从原条目与此目录构建，不保存另一份条目数据库。初版不保存可重建的条目计数和搜索索引。

关联关系为：folder ID → conversation document key → 现有条目。条目唯一键继续包含类型、document key 和 record ID。对话名称不是身份，文件夹路径也不作为新对象的身份。

原书签使用 `folderPath` 和以路径为键的 folder 记录；移动/重命名涉及重写路径及 journal。这套成熟的交互规则可以借鉴，但新标记目录使用稳定 folder ID，改文件夹名只更新元数据，无需改全部正文或定位信息。第一版不触碰原书签实现。

### 名称、来源和定位

- 展示优先级：非空 customTitle → 有效的现有 document.title → 未命名对话。
- customTitle 只修改插件内名称，不修改 ChatGPT；清除自定义值后恢复来源名称。后续页面标题更新不能覆盖用户自定义值。
- 名称采集仅在已经确认会话 ID 的页面/Reader 入口做同步被动读取，优先复用已有标题，再读与当前会话 ID 匹配的可见会话链接；浏览器标题作为经过校验的后备。通用标题、空值、URL 和 ID 不覆盖有效名称。名称随用户创建或管理操作保存，打开资料库不批量改写历史记录。
- 不主动请求所有历史会话来补名字；旧记录名称缺失时可由用户改名或下次访问该会话时补齐。
- 来源 URL 仍保留，用于打开原页，且校验其 ChatGPT 会话身份。分组不依据 URL 字符串，因项目路径与普通路径可能指向同一 ID。
- 恢复定位仍使用 conversation ID、assistant message ID、引用及现有 selectors。改名、文件夹移动只改变组织信息，不改变任何锚点。来源消息未加载或原页失效时不删除记录。

## 4. 写入、兼容与批量规则

- 没有新目录的旧数据直接在“未分类”显示；打开界面不触发原始资料迁移。用户首次命名或归档才写入组织信息。
- 目录写入复用后台存储队列，每次先读最新版本并校验 expected revision；校验同级重名、父级存在、循环、最大深度后再保存。条目写入继续使用原 CRUD 的修订校验。
- 目录操作不和正文搬迁捆绑。批量移动只修改组织目录；批量删除/改色仍按现有条目接口执行。内存队列不是崩溃恢复事务，不声称跨多次存储调用全有或全无。
- 保存应答丢失时先重读核对目标状态；已达到目标的移动/改名不重复写。后台重启重读持久化目录，不能复用失效内存 revision。
- 不自动把“目录读取失败”当“没有文件夹”；保留错误与重试，不用空目录覆盖。孤立 folder 引用在未分类中可见并可重新归档；原始条目可继续打开和定位。
- 文件夹删除先沿用必须为空的规则。删除一个类型下某对话的全部条目不删除 ChatGPT 对话，也不连带删除另一类型。保留其自定义名称和归档，供同一对话未来新增条目继续使用。
- 批量管理区分对象：对话级选择提供整段移动；展开后的条目级选择提供删除、高亮改色。两种选择模式互斥，避免勾选一条高亮却移动了未选条目。两级均显示实际选中范围与数量，切文件夹/类型/搜索清空选择。
- 删除与改色统计实际成功、缺失、失败；失败项留下供重试。确认后新增的条目不自动加入已确认批次。写成功而刷新失败只重读，不重复写入。
- 旧书签导入导出和云备份目前不包含高亮/注释及新组织目录；不能宣称它们已被备份。若要求可导出的完整标记备份，需要将组织目录和原始标记包一并设计版本化导出/导入，作为单独确认的交付范围。

## 5. UI 修正建议

### 左侧导航

资料库类型和设置分类使用同一导航项构造与样式：显式图标槽、文本槽和可选计数槽；统一行高、字重、行间距、内边距、圆角、焦点和选中态。作为下一版预览基准：默认文字 14px、模块标题 16px、图标 18px、行高 40px、行间距 4px，随现有字号设置缩放。去掉同时堆叠的同强度“高亮”和“全部对话”选中块，文件夹层级靠缩进和较轻状态体现。

这些是组件令牌目标，不能直接在生产 CSS 中写一组硬编码值。先核对真实主题与字号配置，再修改共享导航组件。

### 消息工具栏与右下角

- 消息操作、选区弹窗、右下角抽屉共用紧凑工具材质和图标尺寸规则，保留各自的生命周期；不把三套监听器合并。消息胶囊用连续外轮廓处理展开接缝，字符/时间仍在右侧稳定排列。
- 右下角默认品牌图标，hover 或键盘焦点进入时变为设置图标，同时沿用向左展开抽屉。点击该按钮直接打开设置分类，删除展开区最左端的重复品牌入口。
- 按钮无论鼠标或键盘激活都只执行“打开设置”，hover 仅改变呈现；无 hover 设备也可以直接点击进入设置，并从设置内到达现有快捷能力。不要让同一按钮依据鼠标时序有时展开、有时导航。
- 打开设置需要明确的目标入口。目前 `BookmarksPanelPort` 只有 show/toggle，没有目标 tab；应增加 UI 层 `show({tab:'settings'})` 或等价接口，已打开时切到设置，不调用 toggle 把面板关掉。无需改变后台业务协议。
- 指针从按钮移入抽屉不收起；Escape / 点击外部收起；关闭设置后恢复焦点且不意外再次展开。仅删除抽屉里的重复图标，不删除面板左上角品牌。

### 设置中的信息页

建议取消“更多”折叠，把现有六项直接放进设置侧栏底部的常显区域：常见问题、更新日志、反馈、关于我，以及好友迹、请我喝咖啡。前四项使用紧凑链接，后两项使用较醒目的并排圆角入口；窄宽度时纵向排列，短窗口可滚动，不压缩点击区域。

点击任意信息页在右侧显示现有内容，同时正确标记该入口并清除设置分类的选中态。点击任一设置分类能直接回到对应内容。保留现有赞助入口显示策略。这样增加实际可见性和一次点击可达性；是否提高点击率需要后续观察，不新增统计埋点或主动弹窗。
