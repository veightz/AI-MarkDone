# ChatGPT 资料库与设置升级

2026-09-11 起稿，2026-09-12 按用户反馈收敛。状态：用户已批准实施；进度见 [实施记录](2026-09-12-library-ui-implementation.md)。产品范围以 [FEATURES.md](../FEATURES.md) 为准。

## 1. 本轮范围

- 仅支持 ChatGPT 页面与 Reader；浏览器仍为 Chrome MV3 / Firefox MV2。
- 资料库集中查看、搜索和管理书签、注释、高亮。
- 三色高亮使用雾蓝、奶油黄、浅珊瑚红。选中文字后，在复制、注释按钮旁选择三色色块；取消此前画笔模式。
- 高亮、注释分别保存，并带有来源页面。点击“打开原页”返回来源；尽可能定位到目标，定位不成功也不妨碍打开页面。
- 设置按功能分类，并提供搜索。输入增强的能力与细项保留，配置按钮和弹层退出官方输入框，统一迁入设置。
- 资料库、设置、抽屉采用统一 SVG 图标；白色新拟态，支持深色；界面文案简短。

不纳入本轮：高亮转注释、重新关联原文、待定位队列、等待原文加载的列表状态、设置固定/仅看已修改、新的持久化开关及完整备份格式升级。先把已讨论功能做好。

## 3. 收敛后的页面结构

保留一个“左侧导航 + 右侧圆角列表”方案，不再提供三套布局或混合“全部资料”视图。根据最新反馈恢复导航层次，避免把减少动作理解成过度扁平化。

- 左侧品牌下方保留“资料库”和“设置”两个按钮，每次展开其中一个区域。资料库展开时显示“书签 / 注释 / 高亮”及书签文件夹，把设置推到底部；点击设置后，资料库收成顶部按钮，设置上移并展开八个分类。切回资料库时反向展开，保留原来的类型、文件夹和设置分类。
- 点击内容类型查看该类型全部记录；点击文件夹切换到书签并筛选对应文件夹。切换时回到第一页、清空临时搜索与批量选择，避免把上一处的筛选带入新位置。
- 右侧显示当前类型或文件夹名称、一条搜索栏和列表；移除重复的顶部类型标签和文件夹下拉框。设置分类仅放在侧栏，右侧显示当前分类或搜索结果。注释、高亮不增加文件夹能力。
- 列表只显示标题/引用摘要、简短次要文字和日期。点击一条后查看完整详情。
- 原页链接、注释编辑和高亮颜色放在详情。重命名/移动/删除等已有操作放入“更多”；批量管理和书签导入导出不作为常驻工具栏动作。
- 每页最多 20 条，超过时提供上一页/下一页。不将全部正文、全部类型或多个预览面板挂在 DOM 中。
- 不显示待定位、等待加载、重新关联、统计卡片、方案说明或其他未讨论的管理能力。

外层容器、左侧选中态、按钮和列表以圆角为主。侧栏与内容区以轻微底色差、边界和留白建立层次，外层保留轻量新拟态，普通行使用分隔线，无逐行大阴影、模糊滤镜或空闲时持续动画。侧栏模块使用约 360 ms 的连续展开/收起动画，右侧内容切换仅轻微淡入；搜索输入不重复触发内容动画。侧栏节点保持挂载，折叠区域移出键盘焦点，遵循系统减少动态效果偏好。展开区域独立滚动，两个模块按钮保持可见；窄窗口也保留左侧文字导航。设置保留分类与搜索，延用现有配置能力。

注释原有当前/全部、复制、插入和模板操作仍要保留在合适的管理入口，不同时铺在列表上。插入只作用于对应会话，追加草稿、不自动发送；现有“插入并删除”成功条件不变。

## 4. 怎样保存，怎样索引

### 原始记录的持久化

推荐保留现有书签与注释存储；高亮使用独立 namespace 的每会话 bundle，复用注释的目标/选区 selector 与后台写入机制。统一资料库只是读取和展示入口，不创建一份重复的内容数据库，也不把高亮伪装成空注释。

每条高亮至少保存：

| 字段 | 用途 |
|---|---|
| `id` | 稳定记录 ID，编辑/删除不依赖位置 |
| `documentKey` | ChatGPT 会话身份，用于按来源分组 |
| `sourceUrl` / document 的页面 URL | 打开原页；页面 URL 必须在保存时保留 |
| `sourceTitle` / document 的标题 | 来源显示与搜索 |
| `assistantMessageId`（可取得时） | 尝试定位到对应消息 |
| `quoteText`、`prefix`、`suffix`、校验后的文本范围 | 重新绘制高亮与尽力定位 |
| `color` | 保存 `blue/yellow/red`，由主题映射颜色 |
| `createdAt`、`updatedAt`、`revision` | 排序与并发更新 |

页面 URL/标题可在所属 document 中保存一次，各记录引用该 document，不要求每条重复完整页面元数据。标题与 URL 用于显示/导航，不作为唯一记录 ID。高亮和注释不会因为正文暂时不可见而从资料库消失。

已有注释继续使用当前持久化开关与后台写入规则，不在界面改版时改变老用户偏好；新高亮按用户要求持久化，不额外增加保存开关。存储失败用现有错误反馈，不展示虚假的保存成功。

### 分类型列表与搜索索引

首次打开资料库时，先读取当前标签需要的记录；切换标签时再加载对应 namespace。共用一套内存索引规则：

1. **记录映射**：`type + id → 原始记录引用`，让不同类型的 ID 不互相覆盖。旧书签暂用现有 identity key 作为适配 ID，后续再单独升级。
2. **页面分组**：`documentKey → 记录 ID 集合`，支持按会话查看；有语义 conversationId 时使用它，不拿消息序号作页面身份。
3. **搜索文本**：为当前类型的记录缓存标准化后的标题、来源标题、引用及注释正文。输入搜索词时在内存匹配，排序结果按数据版本与筛选条件缓存。只把当前页的 20 条投影到 DOM，不把全部匹配内容渲染出来。

收到存储变更通知时重新读取受影响 bundle，更新其映射和搜索文本。关闭面板后缓存可以释放，下次从原始记录重建。因此索引可重建，缓存丢失不影响原记录。第一版不新增永久全局搜索索引或全文搜索引擎。

书签已存在 `aimd:bookmarks:index:v1`，先沿用，不在本轮视觉重构里重建它的存储协议。现有本地导出与 Google Drive 快照只备份书签，界面应如实说明；扩展完整备份另行讨论。

### 对旧书签数据的风险控制

第一阶段仅更换展示入口。原有 bookmark key、`aimd:bookmarks:index:v1`、文件夹数据、导入导出格式、后台增删改服务都不改。打开新资料库、切标签、搜索、翻页只读取，不触发迁移、去重修复、改 ID 或重写正文。用户主动编辑/删除时仍调用原有用例。

高亮写入独立 namespace，注释沿用原存储，避免新类型覆盖旧书签键。内存索引只引用原记录，不回写为一套“新书签”。UI 改版不能带来静默删除、自动合并或批量转存。

需要验证的真实边界：新列表是否遗漏已有书签、修改/取消是否仍指向同一旧 key、文件夹筛选是否完整、导入导出是否保持兼容、失败回读是否误显示为空。这些风险需要回归验证，不能承诺零风险，但不需要为改 UI 承担存储迁移风险。

书签稳定身份的升级另立任务，在用户明确确认后做。不会把它混进这轮资料库界面重构。

## 5. 定位的实际边界

保存来源页面是明确能力；精确定位是附加尝试。打开来源后，已有稳定消息身份和足够文本证据时复用当前导航/选区解析路径；没有匹配则仍停留在来源页面。用户不需要理解挂载、hydration 或重锚状态。

现有注释本来就保存消息身份、exact/prefix/suffix 和文本范围，可复用。文字位置需要校验引用，不能只取全文第一次出现的位置。DOM path 和像素只作提示，不作为永久身份。高亮恢复继续消费已有页面生命周期/Surface 通知，不新增全历史滚动扫描、独立轮询或主动 conversation GET。

现有书签不是纯像素定位：已经保存 `messageId`，但保存键与部分匹配仍受 position 约束；同一 ID 换了序号可能被当成冲突。这是后续书签可靠性升级的具体入口，不需要在本轮资料库界面暴露新的状态或修复流程。

## 7. 实施顺序

1. 确认资料库、设置、图标和文案，完成现有操作的界面去向检查。
2. 接入现有书签/注释服务与设置服务，迁移输入增强配置入口。
3. 实现独立高亮记录、来源页面保存、选区三色色块、页面与 Reader 的恢复展示。
4. 接入统一内存索引与来源页面跳转，检查原有导入导出、并发更新与旧设置。
5. 书签稳定身份、旧记录迁移与完整备份作为独立后续议题，不顺手塞入本轮。

关键验收：真实选区→色块→保存→刷新；注释/高亮类型互不转换；来源页面可打开；目标未找到不阻断页面导航；重句不误标；设置 false 和父子项保留；多 tab 更新不覆盖新记录；Chrome/Firefox 构建与旧操作回归。

当前 content-feature graph gzip 为 464.32 / 465 kB，接入生产前需处理加载/依赖体积。原型不增加生产入口依赖，也不提高门禁。
